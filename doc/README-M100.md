# Tandy Model 100 / 102 / 200

Issue #334. `mmemu-plugin-m100.so` (`src/plugins/machines/m100/`) makes the
Kyocera-built portables: the Tandy Model 100 (`model100`, alias `m100`),
the Model 102 (`model102`) and the Tandy 200 (`model200`), on the 8085 core
(`doc/README-8085.md`). They are built from the chips described under
[Devices](#devices): each is a standalone C++ class under
`src/plugins/devices/`, compiled into the machine plugin (as the CoCo plugin
does with the MC6821 and MC6847), with unit tests under its `test/`
directory.

References: VirtualT (Stephen Hurd, Ken Pettit; BSD licence) for how the
Model 100/102/200 use the chips, MAME (`kyocera.cpp`, `kyocera_v.cpp` and
the device files named below), the Model 100 Technical Reference Manual,
the chips' data sheets, the Bitchin100 wiki and Brian K. White's `pdd.sh`
for the TPDD protocols. The code is mmsim's own; each file names what it
follows.

## Machines

```
./bin/mmemu-cli -m model100          # or m100, model102, model200
./bin/mmemu-gui -m model100
```

The 8085 runs at 2.4576 MHz (the 4.9152 MHz crystal halved); time in the
machine is counted in its clocks.

### ROMs

The system ROMs are Microsoft / Tandy / Kyocera copyright: they are not in
the repository. Put them in `roms/m100/` (gitignored, except
`hardware.sym`) or in the directory `$MMEMU_M100_FIRMWARE` names:

| machine    | file         | size  | also accepted |
|------------|--------------|-------|---------------|
| `model100` | `m100.rom`   | 32 KB | MAME `m100rom.m12`, VirtualT `M100rom.bin` |
| `model102` | `m102.rom`   | 32 KB | `m102rom.m12`, `M102rom.bin` |
| `model200` | `t200.rom`   | 72 KB | VirtualT's `T200rom.bin`; MAME's 96 KB region; MAME's three chips `rom 1-1.m15` (32 KB), `rom 1-2.m13` (8 KB), `rom 2.m14` (32 KB) |

The Model 200's 72 KB file is VirtualT's layout: the 40 KB main ROM
(`$0000-$9FFF`) then the 32 KB second ROM (MULTIPLAN, bank 1). Without its
ROM a machine is still made, with a warning naming the file, and a stand-in
ROM that writes "NO ROM: PUT M100.ROM IN ROMS/M100/ ..." on the LCD (the
stand-in is generated by mmsim and contains no copyrighted code).

### Model 100 and 102

Memory:

| address       | what |
|---------------|------|
| `$0000-$7FFF` | the 32 KB ROM; the option ROM socket while port `$E0` bit 0 is set (an empty socket reads `$FF`) |
| `$8000-$FFFF` | RAM, ending at `$FFFF` and going down 8 KB a module: 8-32 KB on the 100, 24 or 32 KB on the 102 (nothing below it: `$FF`) |

I/O ports (each block mirrored over its 16 ports):

| port      | read | write |
|-----------|------|-------|
| `$A0`     | -    | Model 100: the modem's control (stored; the modem is not emulated) |
| `$B0-$BF` | the 81C55 (`port & 7`) | the 81C55 |
| `$C0-$CF` | the IM6402's received byte (and clears DR) | the byte to send |
| `$D0-$DF` | status: 0 CD, 1 OE, 2 FE, 3 PE, 4 TBRE, 5 RP, 6 +5 V, 7 /LPS | the IM6402's control (bits 0-4: stop bits, even parity, no parity, word length) |
| `$E0-$EF` | the keyboard rows (active low) | 0 option ROM, 1 printer /STROBE, 2 the RTC's STB, 3 cassette motor |
| `$F0-$FF` | the LCD (A0 low: status; high: data) of every selected HD44102, ORed | instruction (A0 low) or data (A0 high) to every selected HD44102 |

The 81C55's port A drives the LCD chip selects 0-7, the keyboard columns 0-7
(active low), the uPD1990AC's C0-C2 (bits 0-2), CLK (3) and DATA IN (4),
and the printer's data. Port B: bits 0-1 the LCD selects 8-9 (bit 0 also
keyboard column 8), 2 /MC, 3 RS-232 (0) or modem (1), 4 auto power-off, 5
BELL, 6 /DTR, 7 /RTS. Port C (input): 0 the RTC's DATA OUT, 1 printer
/BUSY, 2 BUSY, 3 bar code reader, 4 /CTS, 5 /DSR. The timer counts the CPU
clock; TIMER OUT is both the speaker's tone and the IM6402's 16x clock (a
count of 8 is 19200 baud).

Interrupts: RST 7.5 is the uPD1990AC's TP (the ROM sets 256 Hz: the
keyboard scan and the clock); RST 6.5 the IM6402's DR; RST 5.5 the bar code
reader (not fitted: never); TRAP the power switch.

### Model 200

Memory: `$0000-$7FFF` a 32 KB bank picked by port `$D0` bits 0-1 (0 the main
ROM, 1 the second ROM, 2 the option ROM, 3 nothing), `$8000-$9FFF` the main
ROM's last 8 KB (always), `$A000-$FFFF` a 24 KB RAM bank picked by bits 2-3
(banks 0-2; a bank beyond the RAM fitted, or bank 3, reads `$FF`). RAM: 24,
48 or 72 KB (default 72). Bank switching code has to run from
`$8000-$9FFF` or RAM, as the ROM's does.

I/O: `$90-$9F` the RP5C01 clock, `$A0` the tone dialler (ignored),
`$B0-$BF` the 81C55 (port A the keyboard columns and printer data; port B
0 column 8, 2 /BUZZER, 4 power cut, 5 BELL; port C 0 /LPS, 1-2 printer, 3
bar code, 4 CD), `$C0`/`$C1` the 8251 USART (data; mode/command and
status), `$D0` the bank register (it reads back), `$E0` the keyboard rows /
0 printer strobe, 1 cassette motor, `$F0`/`$F1` the HD61830 (data;
instruction and status). RST 7.5 is a 300 Hz toggle of the clock divided by
8192 (150 rising edges a second, as MAME); RST 6.5 the 8251's RxRDY.

### Keyboard

The matrix is MAME's (nine columns strobed by the 81C55, eight rows read at
`$E0`); the Model 200 has the same one. The GUI sends keys positionally (the
Model 100's layout is a PC's: Shift+2 is `@`). Special keys: Esc is ESC, Alt
GRAPH, right Alt CODE, Home NUM, F1-F8 the function keys, F9 PASTE, F10
LABEL, F11 PRINT, F12 PAUSE/BREAK, Backspace/Delete DEL/BKSP; CAPS LOCK
latches as the real key does. `type TEXT` holds SHIFT where it is needed.

### Display and sound

The LCD is shown at twice its size (480 x 128, or 480 x 256 on the 200) in
two colours: dark dots on a greenish-grey panel, with an 8-pixel border.
The speaker is the 81C55's TIMER OUT while port B bit 2 is low and bit 5
high, or bit 5 itself while bit 2 is high (MAME's i8155_pb_w); it goes to
the host audio output as the other machines' does (about 43.9 kHz, a DC
blocker after it).

### Option ROMs

The socket takes a ROM of up to 32 KB (Multiplan, T-Base, Lucid, Ultimate
ROM II, TS-DOS, the ROM2 / REX images, ...): CLI `rom optrom FILE.bin`
(`rom optrom remove` empties it), the GUI's Control > ROM Sockets, MCP
`rom_socket`, or as a cartridge: `cart FILE.bin`, `-i FILE.rom` (a `.bin`
given to `-i` is loaded into memory as a raw binary, as on every machine).
On the 100/102 the ROM's own code (or BASIC's `CALL 63012`) switches it in
with port `$E0` bit 0; on the 200 it is ROM bank 2. REX's flash writes are
not emulated.

### RS-232, TPDD, printer, cassette

`serial SPEC` attaches the far end of the IM6402 (the 200: the 8251):
`none`, `loopback`, `file:PATH` (a capture of what is sent), `tcp:PORT` (a
listening socket on localhost), `tpdd:DIR` / `tpdd2:DIR` (a Tandy Portable
Disk Drive serving a host directory) or `tpdd:IMAGE` (a `.pdd1`/`.pdd2` or
raw disk image). The UART runs at the rate the 81C55's timer sets (BASIC's
`STAT`, TELCOM's `STAT`); the TPDD answers at whatever rate the computer
uses.

TPDD use: `serial tpdd:/home/me/m100files`, then load TS-DOS (from an
option ROM, or a DOS-on-demand loader)
or any TPDD client; files in the directory appear as `NAME  .BA`, `.DO`,
`.CO`, and sub-directories as TS-DOS's `NAME.<>` entries. Saving creates
files there.

`serial printer:PATH` sends what is printed to a host file
(`printer:none` stops); the printer is always ready.

The cassette is `.wav` only (the Model 100's 1200/2400 Hz FSK as audio):
`tape mount FILE.wav` (play), `tape record` / `tape save FILE.wav`. SOD drives
the output and SID reads the comparator; the motor relay is port `$E0` bit 3
(the 200: bit 1). Uses the CoCo plugin's recorder (`coco_tape.cpp`).

### Power

The screen buttons: **POWER** is the power switch. Turning it off raises
TRAP (the ROM saves its state and turns itself off through port B bit 4);
after 50 ms the power goes anyway (MAME's hold-up time). Turning it on
restarts the 8085 with RAM kept, as the batteries do. The ROM's automatic
power-off (port B bit 4) also turns it off: press POWER to wake it.
**RESET** is the reset button on the back (RAM kept). The frontends'
`reset` is that button.

### Snapshots

The machine state (RAM, the bank registers, all the chips) is in the
`system` bus's state, with the 8085's own, as for the other machines.

### What has been checked, and what is unverified

The tests use mmsim's stand-in ROMs only. By hand, with the real ROMs
(VirtualT's `M100rom.bin`, `M102rom.bin`, `T200rom.bin`; not in the
repository): all three boot to the main menu (29638 / 19590 bytes free),
BASIC runs (`PRINT`, `BEEP`), `OPEN "COM:98N1E"` sends to `serial file:`,
`LPRINT` reaches `serial printer:`, `TIME$` runs, Multiplan (the 200's ROM
bank 1) starts, and TS-DOS 4.00 as an option ROM (`CALL 63012`) lists a
`serial tpdd:DIR` directory. A cold start sets the clock to 00:00:00 on
01/01/00 (the ROM does it); set it with BASIC's `TIME$` / `DATE$`.

The parts most likely to need tuning:

- The keyboard timing: typed keys are held 60 ms with 40 ms gaps (fine for
  BASIC and the menus; key repeat and fast typing not checked).
- Port C's printer and RS-232 handshake polarity (/BUSY, BUSY, /CTS, /DSR)
  and the `$D0` status bits 0 and 5-7: VirtualT and MAME disagree (MAME
  reads `$60`, never sets bit 7 /LPS and leaves its error bits unfinished;
  VirtualT reads bit 7 set and 5-6 clear). mmsim sets 5-7 (no low-battery
  warning) and 0 clear (no modem carrier).
- The Model 200's RST 7.5 rate: MAME's 150 Hz divider is followed;
  VirtualT ticks every model at about 256 Hz.
- The Model 200's 8251 clock: the 81C55's TIMER OUT is assumed to clock
  TxC/RxC (as VirtualT's baud rate from the timer implies); MAME does not
  wire it. /CTS is not modelled.
- The LCD's busy flag (always ready) and the HD61830A's internal font (a
  stand-in: the Model 200 uses graphic mode).
- `LPRINT` ends a line with CR only on the printer file; whether the ROM
  should send LF is unchecked.
- The cassette (`.wav`) has not been tried with `CSAVE` / `CLOAD`.
- The modem, the bar code reader (RST 5.5), the Disk/Video Interface, the
  RAMPAC and REX flash writes are not emulated; nor are the NEC PC-8201A
  and the Olivetti M10 (MAME's `pc8201`, `m10`), which share most of the
  design.

## Devices

### HD44102 column driver and the Model 100 LCD (`hd44102/`)

`Hd44102`: one 50 x 32-dot column driver with 4 pages x 50 bytes of display
RAM (bit 0 the top dot of a byte). Offset 0 is the instruction register
(write) and status (read: bit 7 busy, 6 count up, 5 display off, 4 /RST
held); offset 1 is display data. Instructions: `$38`/`$39` display off/on,
`$3A`/`$3B` count down/up, `pp111110` display start page, `ppyyyyyy` set
page and column (0-49; other values ignored). Data accesses step the
column, wrapping 49 -> 0 (up) or 0 -> 49 (down). Reads come through an
output latch, so the first read after setting the address is a dummy, as
the data sheet says and VirtualT's "fresh pointer" logic produces. A busy
time per access (in the caller's units, `setBusyTime` + `tick`) is
optional; it defaults to 0 since neither VirtualT nor MAME model it.

`M100Lcd` composes the 240 x 64 panel from ten of them. The geometry
(MAME `set_screen_offsets((i % 5) * 50, (i / 5) * 32)`, VirtualT
`SetByte`):

| chips | panel rows | panel columns |
|-------|------------|---------------|
| 0-4   | 0-31       | 0-49, 50-99, 100-149, 150-199, 200-239 |
| 5-9   | 32-63      | the same      |

Chips 4 and 9 have only their columns 0-39 wired (4 x 50 + 40 = 240). The
ten active-high chip selects come from the 81C55: port A bits 0-7 select
chips 0-7, port B bits 0-1 chips 8-9 (`setSelectFromPorts`); the same
lines strobe the keyboard columns. An I/O access at `$F0-$FF` goes to every
selected chip (A0 picks instruction/status or data); reads OR the selected
chips. The HD44103 common driver only scans the rows and has no state.

### HD61830 LCD controller (`hd61830/`)

`Hd61830`: the Model 200's 240 x 128 controller. Offset 1 is the
instruction register / status (bit 7 busy), offset 0 data (the Model 200's
`$F1` / `$F0`). Instructions `$0` mode, `$1` character pitch, `$2` number
of characters, `$3` time divisions, `$4` cursor line, `$8`/`$9` display
start, `$A`/`$B` cursor address (with the low-byte carry quirk), `$C`
write, `$D` read (dummy-read latch), `$E`/`$F` clear/set bit. The display
RAM is external (the Model 200's 8 KB; `setRamSize`). `render(w, h)` draws
graphic mode (the Model 200's: 40 bytes of 6 dots, 64 + 64 rows) and
character mode with cursor, cursor blink and character blink (`frame()`
toggles the blink every 32 frames, as MAME).

The HD61830A's internal character ROM is not reproduced; no freely
licensed dump exists. `FONT_5X7` ($20-$7F) is generated from mmsim's own
MC6847 glyphs; katakana and the 5x11 characters render blank. An external
CG can be attached (`externalCg`). The Model 200 uses graphic mode only.

MAME compares the cursor line with `cursor position + 1`, which never
matches the 8th line of an 8-line cell; mmsim uses the register value as
the line, so `$4` = 7 underlines.

### 8155 / MSM81C55 RAM-I/O-timer (`i8155/`)

`I8155`: 256 bytes of RAM (`readRam`/`writeRam`) and eight I/O registers
(`readIo`/`writeIo`, address & 7): command/status, ports A, B, C, timer
low/high. Port C modes ALT1-ALT4 including the strobed handshakes
(`setStrobeA/B`, INTR/BF/INTE in the status). The 14-bit timer counts
`tick(clocks)` with its four output modes (single/continuous square wave,
single/continuous pulse), start/stop/stop-after-TC, a new count taking
effect at the next TC, and the TIMER status flag (cleared by a status read).
`tick` returns the number of TIMER OUT rising edges, so a UART clocked by
TIMER OUT can be advanced by that many clocks. Callbacks: `inPa/inPb/inPc`,
`outPa/outPb/outPc`, `onTimerOut`, `onIntrA/B`. The count readback follows
MAME (twice the count left in the half, bit 0 set in the first half).

On the Model 100 the timer runs at 2.4576 MHz: TIMER OUT is both the
speaker tone (selected by port B bit 2) and the IM6402's 16x clock, so a
count of 8 is 19200 baud.

### IM6402 UART (`im6402/`)

`Im6402`: control word (`writeControl`, bits as the Model 100 wires port
`$D0`: 0 SBS, 1 EPE, 2 PI, 3 CLS1, 4 CLS2), `writeTbr`, `readRbr`,
`dataReceivedReset` (`readData` does both, as `IN $C0` does), status flags
DR, TBRE, TRE, OE, FE, PE, the TRO pin, master reset. The transmitter and
receiver are clocked at 16x the bit rate (`tickTx`, `tickRx`, or `tick16x`
for both); a received character lands at the centre of its first stop bit.
`onDr` is the Model 100's RST 6.5. The far end is a `SerialEndpoint`
(`setEndpoint`, or `attachSerial(spec)`).

### 8251 USART (`i8251/`)

`I8251`: the Model 200's RS-232 port (`$C0` data, `$C1` mode/command and
status). After a reset (or a command with IR) the first control write is
the mode: baud factor (x1, x16, x64; 00 synchronous, accepted but not run),
5-8 bits, parity, 1/1.5/2 stop bits; then commands: TxEN, DTR, RxE, SBRK,
ER (clears the errors), RTS, IR, EH. Status: TxRDY (the buffer is free:
not gated by /CTS or TxEN, as the data sheet says), RxRDY, TxEMPTY, PE,
OE, FE, SYNDET (0), DSR (the far end's). The transmitter and receiver
count TxC/RxC (`tick`, `tickTx`, `tickRx`; the Model 200 drives both
from the 81C55's TIMER OUT); a character lands at the middle of its first
stop bit, RxRDY (`onRxRdy`, the Model 200's RST 6.5) rises if RxE is set,
and a receiver without RxE ignores the line. /CTS is not modelled. The far
end is a `SerialEndpoint`.

### Serial endpoints (`serial_endpoint/`)

`SerialEndpoint` is the byte-level far end of a UART, with modem lines.
`makeSerialEndpoint(spec)` understands `none`, `loopback`, `file:PATH`,
`tcp:PORT` (a listening socket on localhost, as the TRS-80's RS-232 port
offers) and any scheme registered with `registerSerialScheme`
(`Tpdd::registerSchemes()` adds `tpdd:` and `tpdd2:`).

### uPD1990AC calendar clock (`upd1990a/`)

`Upd1990a`: the Model 100/102's RTC, with pins `setC` (C0-C2), `setDataIn`,
`setClk`, `setStb`, `setCs`, `setOe` (and `setPins` for the Model 100's port
A update), outputs `dataOut()` and `tp()`/`onTp` (RST 7.5). Commands:
register hold, shift, time set, time read, TP 64/256/2048 Hz, test mode.
The 40-bit register is seconds, minutes, hours, day (BCD), weekday and
month. The `Upd4990a` variant adds the year byte, serial command mode
(C0-C2 high), TP 4096 Hz and the 1/10/30/60-second interval modes (those
are uPD4990A commands; the uPD1990AC has only three command pins).

Time runs on emulated time (`tick(cycles)` at `setInputHz`, default
2.4576 MHz) and starts from host local time plus an offset (`syncToHost`,
`setOffsetSeconds`); a time set moves the offset. Time set holds the
counter until hold/shift/read, and the next second then comes 31/32 s
later (MAME's divider analysis).

### RP5C01 calendar clock (`rp5c01/`)

The Model 200 uses a Ricoh RP5C01 at `$90-$9F` (MAME `tandy200`, VirtualT
`rp5c01_read/write`), not the uPD1990AC. `Rp5c01`: sixteen 4-bit
registers, the mode register's block select (time counter, alarm, two RAM
nibble blocks), timer and alarm enables, 12/24-hour mode, the leap-year
counter, the reset register (alarm reset, divider reset, 16 Hz / 1 Hz
off) and the /ALARM pin (`alarmPin`, `onAlarm`). The same host-time-plus-
offset scheme as the uPD1990AC.

### TPDD / TPDD2 (`tpdd/`)

`Tpdd` is a `SerialEndpoint`: attach it to the UART (`serial tpdd:DIR`,
`serial tpdd2:DIR`, or an image path). Operation mode (both drives):
directory reference (reference, first, next, and on the TPDD2 previous and
end), open (write new, append, read), close, read, write, delete, format,
drive status, condition, rename, with the drive's error codes. The TPDD2
adds bank 1 (type + `$40`), version (`$23`), system information (`$33`)
and the sector cache commands (`$30` load/commit, `$31` write, `$32`
read). The TS-DOS extensions VirtualT implements are there too:
sub-directories as `NAME.<>` entries (open to enter, `PARENT.<>` to leave,
open-for-write to create) and the "DME" request (`M1\r` then type `$08`;
the `M1\r` holds across other requests, such as the status TS-DOS asks for
in between, until the CRs TS-DOS sends after the answer).

Storage: operation mode works on a host directory; files appear in 6.2
form (`HELLO .BA`), longer host names as-is. Sector-level access (the
TPDD1's FDC mode: `M`, `D`, `F/G`, `A`, `B/C`, `R`, `W/X`, `S`, answered
with 8 hex characters; the TPDD2's sector cache) works on a disk image:
pdd.sh's `.pdd1`/`.pdd2` (per sector: size code, 12 ID bytes, 1280 data
bytes) or a raw 100 KB / 200 KB dump, written back on every change.

Limits: the drive's on-disk file system is not interpreted, so operation
mode on an image (rather than a directory) reports "no disk" for file
commands; both TPDD2 banks see the same directory; format leaves a host
directory alone; mechanical timing is not modelled (answers are queued
at once and paced by the UART).
